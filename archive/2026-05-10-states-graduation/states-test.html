4 · Rules

Empty

  • Inline for table/list zero-results. One line, link to clear filter.
  • Block for panel-level. Icon-24, title, ≤2-line body, optional secondary action.
  • Page for first-run. Disc icon (48px, paper-tint or tint-alert), section-size title, body, primary action.
  • Distinguish fresh ("nothing yet — invitational") from filtered ("no results — corrective"). Different icon, different copy.
  • Never use a sad face or apologetic copy. Empty is not failure.

Loading

  • Default to skeleton when shape is known. Match real row counts and column widths so layout doesn't jolt on swap.
  • Spinner only when shape is unknown or the wait is action-bound (button submit, refresh).
  • Skeleton pulse: 1.6s ease-in-out, opacity 1 ↔ 0.55. Slow and quiet — never strobe or shimmer.
  • Color: --heat-1. Same hue family as paper-tint, no gray blocks.
  • Show skeleton only after ~200ms — for sub-200ms loads, show nothing (avoids flash).
  • Reduced motion: pulse pauses at static 0.7 opacity.

Error

  • Page when the whole view failed (fetch, route). Retry button, plus secondary "go back".
  • Banner (.notice-banner.is-alert) for partial / scoped failures. Inline above the affected region. Dismissible.
  • Tint disc / banner with --tint-alert (rust pastel). Icon and text stay --ink. No full red panels.
  • Always offer recovery: retry, refresh, or "contact admin". Never a dead-end.
  • If a request ID exists, show it in monospace at the bottom (collapsed/small).
  • Use alert-triangle for page-level fail, alert-circle for inline banner.

Notice (not an error)

  • Permission, quota, scheduled-downtime, read-only — these are informational, not failures.
  • Use .notice-banner.is-caution (amber tint), icon help-circle.
  • No retry button — tell the user what to do (ask owner, upgrade plan, wait).
  • Same primitive as error banner; only the modifier and icon change. One component, two intents.

Anti-patterns

  • No spinning sub-skeletons. Skeleton OR spinner, not both.
  • No full-page spinner if you have a skeleton that fits.
  • No copy like "Oops!" / "Something went wrong" alone — always say what failed and what to do.
  • No empty-state illustration that's just a smaller version of the loading skeleton. They must read distinct.

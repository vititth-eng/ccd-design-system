Phase 1.16 — buttons primitive

Five conventions in flight today (.btn--primary BEM in preview, .btn.primary compound in coherence-test, .btn-soft + .btn-link single-dash in tables.css, .btn-primary referenced in modals.css comment but never shipped, .btn-cancel at 5px radius in onboarding). This sandbox picks one and graduates as buttons.css.

Legend

Variant intent in this system, ranked by emphasis:

  • Primary — brand fill, mid-blue. The single most important action on the surface. One per surface, ideally.
  • Strong — ink fill, navy. Alternative primary when navy dramatic-on-paper reads better than brand mid-blue (hero CTAs, dark-mode contexts).
  • Ghost — paper + rule. Secondary action paired with primary (Cancel / Back / Skip).
  • Soft — --tint-neutral fill, no border. Tertiary action in dense contexts (table toolbars, row-detail, inline filter bars). Holds shape on tinted canvas because tint-neutral is categorical, not surface.
  • Link — text-only, brand. Inline action inside prose or compact cells. Already shipped via tables.css.
  • Danger — rust fill. Destructive confirmation only (delete, archive, irreversible). Never primary on a surface where it's not the user's task.

Candidate A — .btn.is-* dot-modifier

Pattern: <button class="btn is-primary">…</button>. Matches the .is-* state vocabulary used inside tables (.is-sortable, .is-clickable) and toasts (.is-positive). One word per axis, no prefix repetition.

Candidate B — .btn-* dash-prefix

Pattern: <button class="btn btn-primary">…</button>. Matches the primitive-namespace pattern of every other graduated component: .f-control / .dlg-modal / .tbl-wrap / .toast-region. Already partially shipped — tables.css uses .btn-soft + .btn-link today.

Recommendation: B. Reuses what tables.css already ships, fits the naming family, and reserves .is-* for state (.is-loading, .is-active) without colliding with variant.

Locked decisions (proposed)

  1. Namespace: .btn base + .btn-{variant}. Reuses tables.css's existing .btn-soft / .btn-link without a rename. .is-* reserved for state.
  2. Variants: primary · strong · ghost · soft · link · danger. Six is the cap — anything more bleeds into chip / pill / tag territory.
  3. Sizes: sm 28 · md 36 (default) · lg 44. md aligns with .f-control 36 row.
  4. Radius: --r-pill on all sizes. No square buttons. Confirmed by §6 + §7 of DESIGN-SYSTEM.
  5. Focus: ring only, --brand color, 2px width, 2px offset. No border-flip. Locked by Phase 1.10 forms rule.
  6. Disabled: dashed border + 60% opacity + pointer-events: none. No cursor: not-allowed (cross-boundary cursor swap reads as glitch — Phase 1.10 finding).
  7. Active: transform: scale(0.98). Skipped while loading or disabled.
  8. Loading: .btn-loading dims label to 0.5, prepends .icon.spin (2.4s pace), kills pointer-events. Spinner pace inherited from icons.css.
  9. Icon-only: .btn-icon makes it square (width = height). aria-label required.
  10. One primary per surface. Doctrine rule, not enforced in CSS.
  11. preview.html migration: .btn--primary / .btn--ghost / .btn--brand refactored in same push pair (.btn--brand → .btn-primary; old .btn--primary ink-fill → .btn-strong). No alias.
  12. coherence-test.html migration: .btn.primary/.brand/.ghost → .btn-strong/.btn-primary/.btn-ghost. Same push.
  13. tables.css migration: shipped .btn-soft there is paper+rule (i.e. ghost semantics). Atomic rename in same push: tables.css .btn-soft → .btn-ghost; new .btn-soft takes over the tint-neutral filled meaning. Per atomic-token-rollout rule, no alias.
  14. tables.css .btn-link already matches namespace — promote rule into buttons.css, drop from tables.css.
  15. Onboarding drift (.btn-cancel, .btn-confirm, 5px radius): logged for Phase 2A in onboarding-radius-drift.md, not touched here.

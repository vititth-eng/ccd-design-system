Data palette — what we have, what's missing

1 · It is not hectic — it is one system with a hole in it

Eleven colour values felt like three competing palettes. They are not. They are four meanings × three roles. A dot is tiny so it can be bright; text must clear 4.5:1 so it is darkened; a bar only needs 3:1 so it sits between. Same meaning, three different jobs. The naming hid it — --d-* reads as "data", but it actually means "mark".

Meaning Dot  tiny · any contrast Text  needs 4.5:1 Mark / bar  needs 3:1
Good --pos --pos-strong NEW — reuses --pos-strong
Normal none — "normal" needs no dot --accent --d-blue
Below bar --cau --cau-strong --d-amber
Well below --neg --neg-strong --d-red = --neg-strong

Two cells in the mark column are the same value as the text column (--d-red is literally --neg-strong). So the "second tier" is really two new values, not a palette. The only true hole is the green mark.

ΔE 28.6 — the most separation still recognisable as warning and danger. Push further and the pair becomes lime and magenta, which stops meaning anything. Cost: amber turns gold and gets loud (7.3:1), which breaks the "amber is the quietest step" rule; red drops to 3.1:1, right on the contrast floor.

A rule has to change either way. CCD-174 says dark amber stays the quietest step. On a dark ground that is unreachable — amber is physically brighter than red, and every pair that forces it costs either a pink-red or a gold. Amber stays quietest on light only.

4 · The dashboard question

A flag scale answers "how bad is this one number". A dashboard that plots several things side by side asks a different question — "which line is which" — and that needs hues chosen to be equally loud, so none looks worse than another. The flag scale is the opposite by design: red is meant to shout.

Flag scale — ordered, loudness is the message

Correct for: scorecards, competency bars, threshold cells, KPI deltas. Wrong for: "Plant A vs Plant B vs Plant C" — Plant C would look like a problem.

A series palette — if we ever need one

Sketch only — not validated, not proposed. Shown so the difference is visible: no step reads as "worse", and none of them is the status red or amber.

Recommendation: do not build this yet. Every chart that exists today — the multi-rater scorecard — is a flag scale. The Power BI survey work is Power BI's own palette, not ours. Build the series tier the day a real multi-series chart is designed, not before; a speculative palette rots and then gets reused wrongly.
